## 1. 角色与流程总览

v2.0 在 v1.0 只读看板的基础上新增**在线表单填写 + 一键提交 + 离线合并**能力,共支持 **16 个模板**在线填写。

| 角色 | 一次完整流程 |
|---|---|
| **员工** | 打开表单 → 填写 → 导出 .xlsx + 生成 .bat → 双击 .bat 自动复制到网络共享 |
| **管理者** | 收集完所有提交 → 双击 `run_merge.bat` → 查看 `Merged/` 与 `Conflicts/` → 人工决定冲突 |

```
                       ↓ (管理者手动触发)
                    merge.py 合并
                       ↓
              Merged\ 合并后文件  +  Conflicts\ 冲突报告
```

## 2. 员工操作 — 填写并提交

### 2.1 首次准备:设置员工资料(一次性)

1. 打开任意可填写表单(例如 <https://jie20009.github.io/npi-checklist/fme-me-portal/form.html?t=T07>)
2. 点击右上角 **"👤 设置员工资料"** 按钮
3. 填入:
   - **员工编号** (例如 `V24001708`,前缀字母可有可无)
   - **员工姓名** (中文或英文均可)
4. 点击 **保存** — 资料存储在浏览器 `localStorage`,下次自动加载

> 员工编号格式宽松:纯数字 `24001708`、带前缀 `V24001708`、带分隔 `V-24001708` 都可,系统会自动规整。

### 2.2 填写表单

1. 从 **模板库** (<https://jie20009.github.io/npi-checklist/fme-me-portal/templates.html>) 找到目标模板,点击 **"✏ 填写"** 按钮
2. 系统自动加载该模板的字段定义,显示分区表单
3. 按字段类型填写:
   - **文本框** — 单行输入
   - **文本域** — 多行输入(如异常描述)
   - **日期** — 点击选择,格式 `YYYY-MM-DD`
   - **下拉** — 点击选择预设选项
   - **数字** — 只能输入数字
   - **只读** — 系统自动填充(如员工编号、提交时间)
4. 部分模板(如 T07 异常登记)支持**重复行**,点击 **"+ 新增一行"** 可添加多条记录

### 2.3 草稿自动保存

- 表单内容**每 5 秒**自动保存到浏览器 `localStorage`
- 右上角显示草稿状态: **草稿**(灰色) / **已保存**(绿色 + 时间戳) / **未保存**(橙色)
- 关闭浏览器后再打开同一表单,草稿会自动恢复
- 草稿按 `(模板编号 + 员工编号)` 分组,不同模板/员工互不干扰

### 2.4 提交(三步:校验 → 导出 → 复制)

#### 步骤 1:点击 **"✓ 校验并提交"**

系统校验所有必填字段与格式,如有错误会显示红色提示框列出错误数量,并标红对应字段。

#### 步骤 2:在弹出的提交窗口点击 **"📥 导出并生成 .bat"**

浏览器会下载两个文件到本机 `Downloads/`:

| 文件 | 说明 |
|---|---|
| `T07_V24001708_20260727_115918.xlsx` | 填写内容(2 个 sheet: `数据` + `_meta`) |
| `submit_T07_V24001708_20260727_115918.bat` | 一键复制脚本 |

#### 步骤 3:双击下载的 `submit_*.bat`

- 脚本会自动把 .xlsx 复制到网络共享 `\\Pvn-lanfs-01\...\FME-ME\Submissions\`
- 提示 "✓ 已成功提交" 表示完成
- 提示 "✗ 提交失败" 时检查:网络共享是否可达、是否需 OA VPN、文件是否被占用

> 完成!管理者下次合并时会看到你的提交记录。**无需邮件、无需上传**。

## 3. 管理者操作 — 合并与冲突处理

### 3.1 触发合并

1. 确认所有员工都已提交(可让员工口头确认,或查看 `Submissions\` 文件数量)
2. 在能访问网络共享的电脑上,进入 `\\Pvn-lanfs-01\...\FME-ME\` 目录
3. 双击 `run_merge.bat`

### 3.2 合并策略(按模板预设)

每个模板在 `config\config.yaml` 中配置了合并策略:

| 策略 | 行为 |
|---|---|
| **append** | 保留所有提交的所有行,重复主键的行**写入冲突报告**由管理者决定 |
| **dedup** | 同主键的行只保留一条,默认 `latest_wins`(最新提交覆盖),其他落入冲突 |
| **matrix** | 矩阵类模板,按"自身行"主键去重,逻辑等同 dedup |

`run_merge.bat` 会**先跑全量合并**(所有 16 模板),再按各模板单独校验。输出:

```
Merged\T07_合并_20260727_120000.xlsx       ← 合并后供后续分析
Conflicts\T07_冲突_20260727_120000.xlsx    ← 需要人工裁决的重复行
Logs\merge_20260727_120000.log            ← 完整日志
```

### 3.3 处理冲突

打开 `Conflicts\T07_冲突_*.xlsx`,每行包含:

| 列 | 含义 |
|---|---|
| `_conflict_key` | 重复的主键值(如异常编号 `AN-2026-007`) |
| `_conflict_count` | 该主键出现次数 |
| `_conflict_winner_source` | 自动胜出的提交(append 留空,dedup 显示最新提交文件名) |
| `_conflict_loser` | 落败来源(append 留空,dedup 显示被覆盖的提交文件名) |
| 其余列 | 原始字段,供你对比 |

**裁决方式**(自由):
- 选定一行作为正式记录 → 复制到 `Merged\T07_合并_*.xlsx` 末尾
- 全部删除 → 不操作(合并文件已不含重复主键)
- 退回员工重填 → 联系员工重新提交

### 3.4 检查合并结果

`Merged\T07_合并_*.xlsx` 是干净的、无重复主键的合并表,可作为月度汇报/BI 分析的输入。

## 5. 常见问题

### Q1:打开表单页空白/字段不显示?
- 确认浏览器联网(SheetJS 库与 JS 模块需从 GitHub Pages 加载)
- 公司 OA 代理环境下,在浏览器设置中关闭代理或加入 GitHub Pages 白名单
- 按 `F12` 打开开发者工具查看 Console 错误

### Q2:草稿丢了?
- 草稿按 `(模板+员工编号)` 绑定,若清空了员工资料或换了浏览器,草稿不再显示
- 同一浏览器同一员工再次打开同模板,草稿会自动恢复

### Q3:.bat 提示"提交失败:无法访问网络共享"?
- 确认已连接公司内网/VPN
- 用 `Win+R` 输入 `\\Pvn-lanfs-01.pvn.corp.pegatron` 测试能否打开
- 不行则联系 IT 加入 BU6 网络共享访问权限组

### Q4:合并后冲突文件太大/太多怎么办?
- 说明有较多重复提交,建议:
  - 检查员工是否重复提交(同一异常编号被多人填)
  - 改用 `dedup` 策略(改 `config.yaml`)自动保留最新,只把冲突行留作日志

### Q5:能在手机上填吗?
- 可以。表单已做移动端适配,手机浏览器打开同一链接即可
- 但 .bat 文件需在 Windows 电脑上执行,所以**导出后请将 .xlsx + .bat 传到电脑**再运行

### Q6:如何修改已提交的记录?
- 直接重新填写并提交一份新的即可
- `dedup` 策略下,新提交会**自动覆盖**旧提交(以员工编号为主键)
- `append` 策略下,新提交会被视为新记录追加,如有冲突需管理者裁决

### Q7:合并会修改原始 Submissions 吗?
- **不会**。`merge.py` 只读取 `Submissions\`,输出到 `Merged\` 与 `Conflicts\`
- 原始员工提交文件永久保留,可追溯
